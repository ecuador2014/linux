Linux de tiempo real para robots, drones y vehículos

HEXAOS es una distribución ligera basada en Buildroot con kernel 6.18 LTS PREEMPT_RT. Una base común, cinco perfiles y una capa opcional de ROS 2. Arranca en segundos y cabe en decenas de megabytes.

Cinco perfiles, una base

Cada perfil añade solo lo que necesita: drivers de kernel, paquetes y servicios de arranque.

humanoid

Humanoides, brazos, cuadrúpedos

Control de actuadores por CAN a 1 Mbit/s, joystick, audio y cámaras.

  • SocketCAN, GPIO, I2C, SPI, IIO
  • Lazo de control en CPU aislada con prioridad RT

drone

Computador de a bordo (PX4 / ArduPilot)

Puente MAVLink serie↔UDP, vídeo con GStreamer y GNSS.

  • socat, gpsd, GStreamer (V4L2/RTP)
  • El failsafe vive en el autopiloto

car

Vehículos autónomos, AGV, rovers

Bus de vehículo CAN a 500 kbit/s y sincronización de sensores por PTP.

  • linuxptp, gpsd, tcpdump
  • Lazo de control en CPUs 2–3, prioridad 85

mini

Robots pequeños (Pi Zero/3/4)

Serie a Arduino/ESP32, WiFi cliente o punto de acceso y MQTT.

  • Imagen de 128 MB (musl)
  • Broker mosquitto, hostapd, pyserial

automation

Pasarelas industriales y de edificios

Modbus, OPC UA, MQTT, RS-485 y CAN con cortafuegos activo por defecto.

  • libmodbus, open62541, nftables
  • MQTT solo en localhost salvo que definas usuarios

Base común

Todos los perfiles

BusyBox, eudev, SSH solo con claves (Dropbear), chrony, watchdog y herramientas de diagnóstico (rt-tests, can-utils, i2c-tools).

  • Ajuste RT en el arranque (S05rt-tune)
  • Supervisor del proceso de control con failsafe

Empezar

Necesitas Linux (Debian/Ubuntu), unos 20 GB libres y conexión a Internet. La primera compilación tarda entre 30 y 90 minutos.

# 1. Dependencias
sudo apt install build-essential git curl \
  wget cpio unzip rsync bc file flex bison \
  libncurses-dev libssl-dev python3 perl \
  qemu-system-x86

# 2. Código
git clone https://github.com/ecuador2014/linux.git
cd linux/distro/hexaos
# 3. Compilar un perfil
HEXA_SSH_PUBKEY=~/.ssh/id_ed25519.pub \
  ./build.sh humanoid

# Con ROS 2 y/o otra arquitectura
ROS2=1 ARCH=aarch64 ./build.sh drone

# 4. Probar en QEMU (root, sin contraseña)
./run-qemu.sh humanoid

Perfiles disponibles: humanoid, drone, car, mini, automation. Más detalle en la guía de primeros pasos.

ISO live e imagen de disco

Cada compilación x86_64 genera también imágenes arrancables por BIOS y UEFI.

ArchivoPara qué sirve
hexaos-<perfil>-live.isoSistema live: corre en RAM, los cambios se pierden al apagar.
hexaos-<perfil>.imgImagen de disco para grabar en USB o SSD, con raíz ext4 persistente.
 
# Grabar en un USB/SSD (comprueba bien /dev/sdX: se borra todo)
sudo dd if=output/humanoid_x86_64/images/hexaos-humanoid.img \
  of=/dev/sdX bs=4M status=progress conv=fsync

# Probar sin hardware
MODE=iso ./run-qemu.sh humanoid
MODE=img UEFI=1 ./run-qemu.sh humanoid
Sin descargas todavía. Aún no se publican binarios precompilados: las imágenes se generan en tu máquina con los pasos de arriba.

Capa ROS 2

ROS 2 Jazzy con Cyclone DDS como capa opcional (glibc). Se compila de forma cruzada con el SDK de la propia imagen y se instala en /opt/ros.

# 1ª vez: falla al final por falta del tarball (es normal)
ROS2=1 ./build.sh humanoid
make -C .buildroot-*/ O=$PWD/output/humanoid_ros2_x86_64 sdk
# genera ros2/output/humanoid_x86_64/ros2-install.tar.gz
./ros2/cross-build.sh humanoid
# imagen final con /opt/ros
ROS2=1 ./build.sh humanoid

En el robot, el servicio S91ros2 lanza tu launch file con prioridad de tiempo real. Detalles en docs/ROS2.md. La variante ROS 2 no se ofrece en ARM de 32 bits.

Seguridad. HEXAOS es software experimental sin certificación. Un robot, dron o coche puede causar daños graves: prueba siempre con el vehículo sujeto, hélices fuera o ruedas elevadas y un paro de emergencia físico independiente de Linux. La consola de root no tiene contraseña (solo desarrollo). Lee SAFETY-SECURITY.md antes de mover un actuador.
